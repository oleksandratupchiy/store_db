## Повторна перевірка Redis/Mongo після виправлення PowerShell

Windows PowerShell **5.1.26100.9818**, запуск через `powershell.exe -NoProfile -File`:
виправлені `redis-demo.ps1` і `mongo-demo.ps1` завершилися з кодом **0**.
Оновлені `redis-demo.txt` та `mongo-demo.txt` містять фактичний вивід саме після виправлення.
Redis виконав усі 11 команд без ERR; рейтинг: Coffee 12, Tea 11, Chocolate 5.

`ValueFromRemainingArguments` отримував один рядок `EXPIRE product:1 120`,
іменований масив у виправленому варіанті — три окремі аргументи.

`testing/check-demo-scripts.ps1`: **7 сценаріїв PASS**, включно з помилкою Docker,
відповіддю Redis ERR при коді 0, відмовою останньої команди ZRANGE,
помилками Mongo copy/shell. Успішні дочірні процеси повертають 0, усі сценарії
відмов — 1. Повний підсумок: `demo-script-checks.txt`.
Ці перевірки не запускають PostgreSQL і не змінюють CSV benchmark.

## Три серії: статистика між запусками

Додатково виконано два виклики існуючого скрипта з `-Reuse`, 50 прогрівами,
200 вимірюваннями й seed=42. Отримано 6 нових повних CSV, 48 рядків метрик;
разом — **9 основних CSV (3 запуски на кожний масштаб)** та 1 smoke CSV, усього
10 вхідних файлів, 80 рядків. Дані не генерувались і не очищувались.

```powershell
$env:MAVEN_ARGS = '-o' # після завантаження залежностей
.\scripts\benchmark.ps1 -Sizes 1000,10000,100000 -Seed 42 -Repeats 200 -Warmup 50 -Reuse
.\scripts\benchmark.ps1 -Sizes 1000,10000,100000 -Seed 42 -Repeats 200 -Warmup 50 -Reuse
python .\scripts\analyze_results.py
python .\scripts\plot_results.py
```

Обидві серії завершилися з кодом 0. Для всіх шести нових проходів імпортні звірки
та перевірки SQL/Mongo перед замірами пройшли. Час імпорту не входить у заміри:
`-Reuse` повторює upsert тих самих даних у MongoDB поза таймером і пропускає генератор.
Кеші не очищувались, використовувалися 50 прогрівів і прогріті кеші ОС/БД.
Контейнери не перезапускались: до/після повторів ID, StartedAt і RestartCount=0
однакові; StartedAt передує першій серії. SQL і MongoDB — дві моделі читання
однакового логічного результату. Повтори — окремі JVM-процеси зі спільними БД
і кешами; повну статистичну незалежність спостережень це не гарантує.
Реальне оточення повторів — PowerShell 7.6.9, решта стеку як у початковому експерименті.
UTC-час, параметри, шість нових файлів і стан контейнерів збережені в
[`repeated_series_manifest.json`](repeated_series_manifest.json).

Стовпчики `median_ms`, `p95_ms`, `mean_ms` первинного CSV описують **один** запуск
із 200 операцій. Нижче — **середнє медіан між запусками**, вибіркове s з дільником
`n−1`, min/max медіан; n=3. Об'єднаний p95 чи медіана всіх 600 операцій не обчислюються:
початкових спостережень у CSV немає. Викиди не вилучались.
Smoke n=1 включено до зведеного CSV окремо, s залишено порожнім, а не прирівняно до нуля.

Машиночитане зведення: [`between_run_summary.csv`](between_run_summary.csv),
32 групи, з них 24 основні з n=3 і 8 smoke з n=1. Вхідні файли та таблиця:

Графіки `median_ms.svg` та `p95_ms.svg` оновлено з усіх реальних первинних CSV:
висота стовпчика — середнє відповідних метрик між запусками, вуса — min–max;
для n=1 вуса не малюються. Середнє p95 запусків не є p95 об'єднаних операцій.

Повне читання має нижчі середні медіан у MongoDB. Для статистики результати близькі:
наприклад, на 100 000 замовлень 11.173 ms (PostgreSQL) проти 11.117 ms (MongoDB),
при s=2.949 і 3.394 ms відповідно. Для ID на 1 000 замовлень розкид особливо великий:
PostgreSQL 10.833–150.003 ms. Фонове навантаження, JVM, мережа й кеші можуть впливати;
телеметрії для встановлення точної причини немає. Три серії дають описову статистику,
без висновку про статистичну значущість або універсального переможця.
